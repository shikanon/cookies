# 智能投放字段填写分析

分析日期：2026-09-14。范围：现有 Cookies 项目、策略、产品、素材和巨量 Connector 数据。

## 结论

可以减少运营重复填写。优先做有来源的字段继承和候选范围收敛，再考虑模型推荐。当前数据不足以可靠地自动确定产品组合、投放预算、出价或转化目标。

两页已统一选择器、目录加载及分支规则，并接入共用智能填写。建议需逐项确认后写入草稿，再由用户保存；不会触发真实投放。

## 字段清单

| 字段 | 现有来源和默认行为 | 可自动化程度 | 数据缺口和确认要求 |
| --- | --- | --- | --- |
| 计划名称 | 项目品牌；新计划固定追加“销售线索增长计划” | 可按品牌、营销目的及排期生成建议 | 当前名称可能与营销目的不符；用户可修改，不作为效果预测 |
| 业务目标 | `ProjectRecord.goal`；缺失时使用销售线索文案 | 项目目标有效时可直接继承 | 需区分真实业务目标与占位文案；不把占位内容当作依据 |
| 策略来源 | 首个 ready/completed 策略任务及其版本 | 唯一有效策略可建议关联 | 多策略没有明确优先级；需确认任务，冻结版本和哈希 |
| 营销目的 | 项目目标和策略 objective；页面已移除关键词建议横幅 | 后续可提供有理由的建议 | 关键词可能冲突；与平台枚举映射仍需运营确认 |
| 账户 | 当前项目绑定且已验证的 Connector 账户；默认首个 | 唯一可用账户可建议补全 | 多账户的品牌、授权和预算职责不能靠顺序推断 |
| 营销产品 | 项目关联 Cookies 产品及账户 Connector 产品目录 | 可检索、过滤；唯一匹配可建议 | 两种来源的 ID 不是同一种身份；平台映射不完整时不能按同名合并 |
| 基础素材 | 已人工确认的 Cookies 版本；Connector 视频、图片、图文、原生视频 | 可按业务分支和媒体类型过滤 | 初始默认首个已确认素材并非相关性推荐；缺少统一的产品关联及效果样本口径 |
| 产品主图 | Connector 产品主图目录，含稳定图片路径证据 | 可检索及检查引用完整性 | 不等同于基础素材；产品归属和内容适用性需确认 |
| 产品名称、品牌 | 产品引用名称快照；平台配置有品牌目录与自定义名称 | 可继承确定的名称 | 项目产品摘要仅提供 ID、名称和平台映射，并未携带完整品牌及卖点 |
| 产品卖点 | 产品、品牌 brief、策略及创意链路存在 selling_points 数据 | 确认产品对应关系后可提出继承建议 | 需按目标产品、审核状态、版本和来源取值；不能直接混用其他产品卖点 |
| 推广文案、搜索词 | 平台表单手工输入；策略和创意有相关文本 | 可作为后续生成建议 | 需要检索同产品已确认内容，控制长度、事实依据和平台限制；必须人工确认 |
| 获客方式、投放载体 | 现有营销目的和获客方式联动规则 | 可收敛到合法选项 | 规则说明“能选什么”，不说明“哪个效果最好”；转换分支会使部分引用失效 |
| 优化目标 | 线索和内容营销使用账户能力快照；其他路径使用对象目录 | 可按准确账户和上下文列出候选 | 必须保存快照身份及上下文；业务目标与转化事件的对应关系需确认；请求失败不编造候选 |
| 投放模式、计费方式 | 平台固定模式及现有计费、出价约束函数 | 明确平台规则可直接派生 | 深度优化及未校准路径仍需执行前检查，不能通过补默认值开放执行 |
| 日预算、总预算 | 项目预算作为计划初值；长期计划按日预算使用，固定周期分摊 | 可展示带计算依据的建议 | 项目预算不天然等于日预算；需要运营明确周期、分配方式和账户额度 |
| 出价 | 平台约束、优化目标、计划预算 | 可校验上下限，不能据此确定最佳值 | 缺少足够的账户历史成本、转化价值及可比样本；运营确认金额 |
| 排期、时区 | 今天起长期投放；项目时区或 Asia/Shanghai | 已确认活动时间可继承 | 当前没有强制关联的活动日历；结束日期和预算周期需一起确认 |
| 落地页、监测链接 | 真实落地页目录或手工 URL；按载体区分 | 可引用已验证、同账户或同项目数据 | 不能生成虚构 URL、像素或事件 ID；载体变化需重新确认适用性 |
| 授权身份、应用、类别 | 当前账户对象目录 | 可过滤、检索并建议唯一候选 | 账户授权和对象适用性必须真实有效；历史引用不等于当前仍可用 |

## 后续智能填写的最小路径

1. 只补空值。每项建议显示来源和依据，用户确认后写入草稿，不覆盖已填写值。
2. 先实现确定性继承：有效项目目标、唯一关联产品、唯一有效策略及规则派生字段。
3. 对多个产品、素材或目标显示候选，不把首个候选当作最优结果。
4. 文案生成单独立项。先建立产品、策略和素材版本关联，再增加有事实依据的生成及评估。
5. 所有采纳结果继续走当前保存、预检和审批流程。金额与平台执行不因“智能填写”获得额外权限。

建议评估采纳率、人工修改率、引用失效率和预检通过率。不要将填写完成率视为投放效果提升。

## 实现入口及边界

- `src/components/DeliveryObjectPickers.tsx`：产品、基础素材、对象和能力目标选择器。
- `src/components/useDeliveryCatalog.ts`：项目和已验证账户范围内的目录请求。
- `src/lib/deliveryChoices.ts`：营销目的、载体及账户切换规则。
- `src/lib/deliveryPlanForm.ts`、`src/api/delivery.ts`：表单、完整 StableReference 和配置间的转换。
- `src/lib/oceanengineBranchConstraints.ts`、`src/lib/oceanengineBidConstraints.ts`：既有分支与金额约束。
- `src/data/api.ts`：项目产品摘要、素材版本、产品和品牌事实，以及 Connector 接口。

已有单元保持独立编辑。新计划保留素材选择标签；保存后隐藏该标签，通过“查看平台配置”管理单元素材，避免通过摘要页重新生成单元。历史只读配置不升级、不自动改写。

## 智能填写配置与边界

- 启用 `COOKIES_DELIVERY_FILLING_ENABLED=true`，默认为 `false`。只能使用真实文本适配器，模拟适配器会在启动校验时被拒绝。
- 直连方舟：`COOKIES_PROVIDER_TEXT_ADAPTER=ark_text`，配置 `COOKIES_ARK_TEXT_API_KEY`、`COOKIES_ARK_TEXT_MODEL`；可选 `COOKIES_ARK_TEXT_BASE_URL`。
- 网关：`COOKIES_PROVIDER_TEXT_ADAPTER=adapter_gateway`，配置已有网关主密钥、模型路由及凭据。模型别名复用 `COOKIES_STRATEGY_TEXT_MODEL_ALIAS`。投放填写开关不依赖策略生成开关。
- API：`POST /api/delivery/v1/projects/{project_id}/filling-suggestions`。请求使用固定字段标识，禁止任意 JSON 路径；必须具备项目访问权限和 `delivery.write`。
- 已批准策略包可选，按包 ID、版本与内容哈希读取。原业务任务策略引用继续保留，不能替代批准正文。
- 模型只能选择服务端候选 ID。返回前重新读取事实和候选，拒绝已失效或版本变化的引用。能力读取失败不回退到固定目标。
- 候选目录逐页读取；每类超过 1000 项时要求缩小搜索范围，不将第一页伪装成全部候选。
- 名称、目标和文案可生成待审文本。产品名称及卖点仅继承已关联产品事实；自然语言限制需要人工核对，禁止宣称会进行字面检查，不能替代语义审查。
- 项目预算只作为本计划总额度的待确认上限；已有计划可引用已保存的日预算、出价和排期，不推断最佳金额。缺少依据时不返回建议。
- 监测链接没有统一已验证目录，因此不生成链接。落地页和授权身份只能使用符合当前分支的 Connector 对象。
- 接受记录保存到现有配置 `compilation_metadata.filling_history`，包含接受字段、理由、数据来源、模型及策略版本。它是审阅记录，不是平台执行授权。
- 当前本地环境未配置真实模型凭据，真实模型烟测尚未执行。自动化测试使用明确标记的测试响应，不能作为真实调用成功的证据。
