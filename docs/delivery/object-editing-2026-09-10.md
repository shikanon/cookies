# 项目与单元的独立状态和编辑

## 稳定对象身份

计划版本记录配置历史，保存配置保留项目和单元 ID。后端按对象给出 create、update、unchanged、blocked，执行只处理必要变更。

已有项目在单元变化时保持原平台 ID。历史草稿 ID 曾随版本变化的项目，只在同一计划下存在唯一确认映射时复用；单元不按名称或位置猜测身份。

缺少父项目、映射冲突或未知提交结果会阻止创建。取消后的新尝试保留旧审批和证据；执行层幂等键同时绑定业务执行与请求，重复请求仍返回同一 Run。

## 界面

项目和单元的配置卡片直接显示“新增、未变更、待同步、待核对”。平台项目 ID 直接显示，单元保留独立编辑入口，不额外展示重复的对象变更列表。

平台配置与对象列表共用编辑器。已有单元当前只开放日预算受控修改：核对当前预算、保存目标、生成具体差异、审批并准备表单，最终保存仍需一次性确认。当前目标预算按整元填写且至少 300 元。

项目字段和已有单元的名称、素材、落地页、出价等尚未开放自动修改。保存普通计划信息不会重建单元或丢失高级配置。

## 平台状态与 Cookies 支持分离

`fields[].platform` 记录平台观察；`fields[].cookies` 记录已实现的编辑流程。普通计划预览不访问浏览器，平台状态为 unknown；尚未创建的草稿为 not_applicable。

展开“字段编辑权限”并点击“检查平台字段状态”，会调用：

`GET /api/delivery/v1/projects/{project_id}/platform-entity-mappings/{mapping_id}/field-capabilities`

服务端检查组织、计划和 confirmed 映射，从稳定账户引用解析平台账户。读取发生在独立 Edge 标签页，完成后关闭；不修改用户原页面，不填写或提交表单。

结果包含账户和对象绑定、时间及字段观察，仅保存在当前界面。再次检查先清除旧结果。缺失、隐藏或非唯一控件保持 unknown，混合禁用的控件组显示部分可编辑。

平台页面可编辑不代表 Cookies 支持，也不保证最终提交校验通过。观察不会放宽执行权限。

## 请求响应发现

一个已有项目编辑页的 62 个 API 响应中，`GET /superior/api/v2/project` 返回 `data[].CanEdit`。读取同时核验 `Id`、`AdvertiserId` 和 `IsDel`。这是项目级权限，不是逐字段权限。

账户接口的 `access_list` 包含编辑开关，前端配置接口也包含规则，但此次未发现完整的逐字段可编辑清单。实现不按开关名称推断字段权限，而是读取当前页面控件的原生、ARIA 和已观察的禁用状态。

实际观察确认项目名称可编辑，而部分营销字段只读。已有单元编辑页也完成只读检查。回归覆盖账户和对象不匹配、跨组织访问、缺失权限、禁用和混合控件、以及 Cookies 规则不误判平台限制。

## 交付及验证

新增两项 Connector 迁移，分别扩展 application 与 douyin_video 类型。部署应先执行正常迁移流程。字段检查复用现有 Browser RPA 配置、已登录 Edge 会话和 Node/tsx 运行时；浏览器不可用时明确报错。

电商现场验证完成原项目复用、第一单元提交与 ID 回写、第二单元 Prepare/Submit 与回写。运行最终 succeeded，三个对象均为 unchanged，全部映射已确认。

相关 Go、TypeScript、浏览器测试及前端构建通过。原始平台数据和内部交接记录不提交到仓库。
