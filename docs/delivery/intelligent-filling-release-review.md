# 智能填写交付审查（2026-09-15）

## 结论

可交付内部验收，定位为平台配置草稿填写工具。正式发布仍需推送新提交、建立对应 PR 并通过全部必需 CI。本轮不推送、不合并、不执行真实平台投放。

## 本版范围

- 平台配置顶部提供统一入口，弹窗选择目标单元、素材与文案数量、附加说明及可选批准策略。已绑定对象继续遵守原编辑边界。
- 生成内容直接应用草稿，不显示接受勾选或理由表。项目字段和单元字段分层应用；取消请求、上下文变化及并发手工编辑受保护。
- 覆盖文案、卖点、关键词、定向、素材及品牌来源。来源采用 brand_name；产品主图与基础素材分别保存。
- 使用现有真实文本 Provider 输入图片和元数据；模拟 Provider 不得作为真实填写结果。
- 预算与出价默认不填写。启用后按项目日预算及权重分配单元预算；只从可比真实历史提取出价中位数，展示范围及依据。金额不得由 LLM 编造。
- 本轮审查补充：偶数历史样本采用中间两项均值并取整到分；若新单元预算与保留的出价冲突，保留原单元金额并提示。

## 验证依据

- 服务端：`go test ./internal/platform/provider ./internal/platform/connector ./internal/systems/delivery ./internal/systems/delivery/httpapi ./cmd/cookies-api`。
- 前端：`npx tsx --test test/delivery-filling.test.ts test/delivery-platform-configuration-contract.test.ts`。
- 构建：`npm run build`，包括 TypeScript 和 bundle 大小检查。
- Playwright：`delivery-plan-preflight.spec.ts` 中 intelligent filling 场景，覆盖公共入口、单元选择、取消、自动应用、保存回显及原有高级配置保护。
- 最新浏览器回归通过，页面用例 54.5 秒。第一次运行在测试环境启动阶段超时；重跑仅将本地 webServer 等待从 5 分钟延长至 10 分钟，未减少测试断言或更改仓库 CI 配置。耗时主要来自测试素材和数据库初始化。
- 本会话此前已在外部 Edge 验证真实方舟多模态生成；本轮金额算法改动由规则测试覆盖，不宣称新增了真实出价效果实验。
- 提交前执行 `git diff --check`。

## 可交付边界

- Connector 视频使用平台提供的封面，不保证是首帧；Cookies 视频提取 0ms 帧。尚未理解完整视频。
- 候选按搜索词或品牌过滤，较多时先按标题和元数据初筛。可能遗漏标题不足或未含品牌的素材；不是基于投放效果的素材排序。
- 模型输出仍需保存前人工检查。自然语言策略、视觉促销信息和事实过滤不能保证文案完全正确。
- 出价建议要求足够的近期同条件真实记录。未验证真实账户下“产生出价建议并取得更优效果”的闭环；资料不足时保留原值，不能作为自动调价或最优出价能力交付。
- 本版未推送。历史已合并 PR 的 CI 不代表本次提交，正式发布须等待新提交的必需 CI。
