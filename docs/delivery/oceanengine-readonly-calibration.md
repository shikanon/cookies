## 1. 边界和结论

本次通过已登录浏览器会话完成只读走查。允许查看列表、详情、诊断、报表和未提交的新建/编辑表单；禁止保存、提交、启停、删除、复制以及修改预算、出价或平台状态。观察期间未遇到登录过期、验证码或权限中断，也没有产生广告对象写入。

本次走查已取得以下连续证据链：

`投放账户 → 项目列表/项目表单 → 单元列表/单元表单 → 数据中心 → 账户/项目/单元/基础素材报表`

本摘要的收口结论见[只读校准收口](./read-only-calibration-closeout.md)，当前目标模型见[`DeliveryIntent` 与平台配置契约](./platform-configuration-contracts.md)：消费端口和 mock/replay 已按 `upstream/main` 的 PR #38 实现更新；历史 schema 保持只读版本边界，不新增兼容 projector。Connector 仍是真实数据影子分析的外部依赖，不是 Delivery 模型实现的前置阻塞。

巨量当前页面的稳定业务骨架应表达为：

`PlatformAccount → PlatformProject → PlatformPromotion → Material/Copy/LandingPage/Identity/CreativeComponent 引用`

因此，内部 Delivery 配置可以继续使用自己的领域名称，但平台适配层不能把内部“广告组 → 计划 → 创意”三个区段直接当成巨量当前页面对象名，也不能假设每个创意组合都有独立、稳定的 Creative ID。

## 2. 页面和动态表单事实

- 项目承担营销目的、营销场景、营销产品、投放模式、用户定向、排期、预算、竞价策略、出价、监测链接和项目名称。
- 单元承担所属项目、投放身份、基础素材、文案、原生锚点、落地页、产品信息、创意组件和单元设置。
- “营销目的 × 营销场景 × 投放模式”会改变后续字段；手动投放比自动投放增加版位、完整用户定向、智能放量、付费方式、搜索快投等配置。
- 优化目标不是页面固定枚举。它依赖已选应用/商品及事件管理中的可用事件资产；当前测试应用允许被选入未提交表单，但该链路没有可用优化目标。既有项目仅观察到 `app内下单` 样本。
- 列表诊断摘要、诊断抽屉事实和生成式 AI 诊断回答是三个不同来源，必须分别保存窗口、新鲜度、版本和 evidence，不能相互替代。

## 3. 空报表 schema 证据

四份报表均直接下载为 XLSX，仅含一个 `Sheet1` 和一行表头，没有数据行。空表只能证明列名与默认粒度，不能证明数值类型、空值、归因口径、汇总关系或数据延迟。

| evidence_id | 默认维度/对象字段（按 XLSX 表头） | 共用指标列数 | 工作表范围 |
| --- | --- | ---: | --- |
| `OE-RPT-ACCOUNT` | `时间-天`；账户标识不在行内，必须从查询上下文补充 | 12 | `Sheet1!A1:M1` |
| `OE-RPT-PROJECT` | `时间-天`、`项目ID`、`项目名称` | 12 | `Sheet1!A1:O1` |

| `OE-RPT-MATERIAL` | `素材名称`、`素材内容`、`素材类型`、`素材ID`；默认没有行内时间列 | 12 | `Sheet1!A1:P1` |

共用的 12 个 XLSX 指标表头为：

`消耗`、`展示数`、`平均千次展现费用(元)`、`点击数`、`点击率%`、`平均点击单价(元)`、`转化数`、`平均转化成本`、`转化率%`、`深度转化数`、`深度转化成本`、`深度转化率%`。

页面标签与导出表头存在稳定别名，例如页面“消耗(元)”导出为“消耗”，页面“优化目标”导出为“转化目标”，比率列在导出中追加 `%`。Connector 必须保存原字段名和 schema 版本后再归一，不能用当前中文显示名直接生成领域字段。

## 4. 对象关联和 Connector 输入

| 页面对象 | 平台稳定证据 | Delivery/Connector 需要的关联语义 |
| --- | --- | --- |
| 投放账户 | 当前账户上下文 | `account_ref`；账户报表行内没有该字段 |
| 项目 | `项目ID` | `platform_project_id`，不得与 cookies `project_id` 或内部 Delivery 计划 ID 混用 |
| 单元 | `单元ID`、所属项目 | `platform_promotion_id` + 父 `platform_project_id` |
| 基础素材 | `素材ID`、素材类型 | `platform_material_id`，再由洞察的对象/资产映射关联内部 Asset/CreativeVersion |
| 优化目标 | 目标显示名、产品链路、事件资产 | 动态目标引用；允许“当前链路无可用目标”，不得伪造完整静态枚举 |

Connector 发布给 Delivery 的事实还必须带查询窗口、平台账户时区、抓取/同步时间、`data_through`、导入批次、字段映射/schema 版本、归因窗口、币种、质量状态和原始证据引用。基础素材默认报表没有行内日期，因此查询窗口必须作为批次元数据保留。

## 5. 只读走查完成判定和剩余未知项

只读走查完成门已经满足：目标账户和导航路径可重复进入；项目/单元主要页面与条件区块已观察；允许导出的四种首要报表已取得 schema；未观察内容均被明确保留为未知项；全程没有把经验或 API 文档枚举冒充页面事实。

以下内容不属于本次走查已证明事实：

- 空报表不能验证真实数值类型、空值、重复、归因、延迟和对账；这些由 Connector Owner 在取得真实数据后验证。
- 当前账户的业务对象集中于同一营销目的和自动投放模式，这是账户服务单一甲方的正常边界，不代表其他模式不存在。
- 未执行保存、校验或最终提交，因此没有证明平台错误码、审核规则和写入幂等性。
- 未验证巨量正式 API 与当前页面字段的一一对应关系；API 仍是获得开发者账号、OAuth 授权后的可选适配器。

业务 Schema 校准应基于本摘要建立版本化条件矩阵、平台对象 schema 和内部配置映射；Connector 接入的正式进入门是数据洞察 Owner 对[消费需求](./insights-connector-consumer-requirements.md)中的对象种类、指标、schema evidence 和交付接口作出确认。
